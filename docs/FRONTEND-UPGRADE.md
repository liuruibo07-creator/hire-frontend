# 三端与招聘流程前端升级

本次仅修改 zhi-mi-front，不修改 jobsearchpro、数据库、网关或现有接口路径。

## 可用功能

- 求职端：蓝白浏览导航、投递卡片、申请进度、我的面试、公司招聘概览。
- 企业端：招聘工作台、候选人状态分组、按职位名称查询、批量更新、面试安排。
- 管理端：深蓝导航与独立审核/用户管理/投递巡检菜单。
- 所有登录用户：全局未读通知；求职者和企业另有未读聊天角标。15 秒轮询，后台标签页暂停。
- 聊天：5 秒同步当前消息及会话列表，快捷回复，标读后刷新全局计数。
- 校园招聘：原独立页并入职位搜索，`/campus` 重定向到 `jobType=实习` 的搜索页，旧链接可用。

## 现有接口下的边界

- 公司不是独立企业库。公司目录按已加载公开职位汇总；搜索与数量排序范围在界面说明。公司概览以一个在招职位作为入口，分批查询其他公开职位进行匹配。无企业 ID 的搜索结果只能按名称匹配，同名公司存在歧义。没有伪造 Logo、简介、规模或认证标识。入口职位下架时可能无法继续打开，页面提供错误状态。
- 面试安排使用 PUT /api/application/applications/{id}/status 的 status=2 与 remark 字段。remark 采用 `[面试安排/v1]` 加 JSON 保存时间、方式、地点、联系人和备注，总长不得超过 500。兼容原有普通文本备注；编辑公开反馈会保留已有面试安排。面试日程从状态为 2 的投递逐条读取详情，因此以最新安排为准，非独立面试历史。页面显示本页最近面试，不提供离线定时推送、接受/拒绝或取消面试假按钮。其他客户端直接覆盖 remark 会丢失安排。
- 申请进度仅显示真实 createTime 和当前 status，不推测历史状态及其时间。未实现撤回、状态历史、内部私密备注、服务端标签。
- 企业备注是公开反馈，求职者可见。批量操作只更新 status（已查看/录用/拒绝），保留已有备注；明确显示部分成功，用户刷新后可重试失败记录。
- 职位详情通过分页查询本人投递恢复“已投递”状态。公司概览和本人投递查询可能需要多次已有接口请求。
